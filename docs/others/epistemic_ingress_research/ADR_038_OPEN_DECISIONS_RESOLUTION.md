## 2. Decision A — Assistant Proposition Semantic Indexing

### 2.1 The Problem
For the Ingress Gate to assign `antecedent_term_id` on user echoes (`CONFIRMED_ECHO`) or corrections (`CORRECTED_NEGATION`), the assistant's prior conversational claim must possess a valid 64-bit integer identifier in `TermArena`. 

In the current codebase, the assistant's realized text is generated by the Small Language Model (LFM2.5-1.2B) under Stage S14 and appended to `CognitiveOrchestrator._history` as unstructured strings (`[("assistant", text)]`). However, the assistant's communicative intent is **already formalized** prior to text generation:
- At Stage S10b, CAPS emits a typed `CAPSResult`.
- At Stage S14, `RealizationInputContract.from_caps()` compiles this intent into a typed contract containing `target_predicate`, `role_bindings` (`ARG0`, `ARG1`, `ARG2`), `polarity`, `epistemic_status`, and `act` (`CommunicativeAct.INQUIRE`, `ASSERT`, etc.).

### 2.2 Evaluation of Alternatives

| Alternative | Description | Architectural Fit | Identity Stability | Memory Cost | P23-H Safety | Verdict |
|---|---|:---:|:---:|:---:|:---:|:---:|
| **1. Parse Assistant Surface Text Post-Hoc** | Run `LanguageIngressGate.admit_and_parse()` on the assistant's own generated text string. | Poor | Low (subject to SLM phrasing jitter) | High (duplicate parsing) | Safe | **REJECTED** |
| **2. External In-Memory Proposition Dictionary** | Store assistant claims in a separate dict outside `TermArena`. | Medium | Medium | Low | Breaks JTMS integration (JTMS requires `term_id` in `TermArena`) | **REJECTED** |
| **3. New Persistent Proposition Registry** | Build a global UUID-based proposition database. | Poor | High | High (disk I/O, schema migration) | Violates Minimum Change Principle | **REJECTED** |
| **4. Intern Intent into `TermArena` via `allocate_term()`** | When CAPS/Realization creates an inquiry/assertion contract, allocate a candidate `LogicalTerm` in `TermArena`. | **Optimal** | **High (Monotonic in-session `term_id`)** | **Zero heap ($O(1)$ preallocated slot)** | **100% Safe (marked `UNKNOWN` / modal)** | **ACCEPTED** |

### 2.3 Ratified Decision (Decision A)
**The assistant's communicative intent proposition is interned directly into `TermArena` upon generation of `RealizationInputContract` at Stage S10b/S14.**

1. **Allocation**: When the assistant formulates an inquiry or assertion (`target_predicate is not None`), `CognitiveOrchestrator` calls `arena.allocate_term(...)`:
   - `predicate_id = symbol_table.intern_concept(contract.target_predicate)`
   - `arg0_id .. arg2_id` interned from `contract.role_bindings`
   - `epistemic_status = EpistemicStatus.UNKNOWN` (for inquiries) or `EpistemicStatus.INFERRED` (for deductions)
   - `polarity = contract.polarity`
   - `scope_id = arena.allocate_scope(scope_type_id=SCOPE_TYPE_MODAL)` (isolated from root facts)
   - Returns: `asst_term_id: int`.
2. **Discourse Tracking**: The orchestrator registers `asst_term_id` into `DyadicDiscourseState`:
   ```python
   self._dyadic_state = DyadicDiscourseState(
       ...,
       active_assistant_seed_term_id=asst_term_id,
       inquiry_type="CLOSED" if contract.act == CommunicativeAct.INQUIRE else "STATEMENT",
   )
   ```
3. **P23-H Purity Guarantee**: Because the seeded term is interned with `scope_id = MODAL` and `epistemic_status = UNKNOWN`, it **cannot unify with root axioms or prove backward goals** during P23-H reasoning. It exists purely as an addressable referent in `TermArena`.

## 3. Decision B — JTMS Retraction Ownership

### 3.1 The Problem
When the user utters a correction (`CORRECTED_NEGATION`), ADR-038 requires:
1. Emitting the corrected belief with `polarity = False`.
2. Retracting the seed hypothesis in `JTMS` via `JTMS.retract_premise()`.

The Implementation Boundary Specification (`DOC-ADR038-IMP-001`) rightly rejected having `LanguageIngressGate` call `JTMS.retract_premise()` directly, as this would violate layer inversion (perimeter firewall directly reaching into the cognitive reasoning core).

### 3.2 Evaluation of Alternatives

| Alternative | Description | Dependency Direction | Testability | P23-H Purity | Complexity | Verdict |
|---|---|:---:|:---:|:---:|:---:|:---:|
| **1. Ingress Gate Directly Calls JTMS** | Ingress Gate imports `ReasoningKernel` and calls `retract_premise()`. | **Inverted (Perimeter $\to$ Core)** | Poor (gate requires live reasoning engine) | Violated (tight coupling) | Low | **REJECTED** |
| **2. Global Asynchronous Event Bus** | Ingress Gate emits `RetractionEvent` to a pub/sub event bus. | Decoupled | Low (event ordering nondeterminism) | Safe | High (adds runtime event broker) | **REJECTED** |
| **3. Typed Retraction Directive Mediated by Orchestrator** | Ingress Gate emits certified proposition with a typed `RetractionDirective`; Orchestrator dispatches to `ReasoningKernel` at Stage S10b. | **Downstream (Perimeter $\to$ Orchestrator $\to$ Core)** | **Optimal (isolated unit testing)** | **100% Preserved (uses existing API)** | **Low** | **ACCEPTED** |

### 3.3 Ratified Decision (Decision B)
**The Ingress Gate emits a typed `RetractionDirective` as part of its gate output; `CognitiveOrchestrator` executes the retraction during the Cognitive Reasoning stage (Stage S10b).**

```text
[Stage S1 Ingress]
LanguageIngressGate.certify_candidate_assertion()
  ├── Identifies `causal_relation == CORRECTED_NEGATION`
  ├── Emits QualifiedLogicalAssertion(polarity=False, antecedent_term_id=seed_id)
  └── Emits RetractionDirective(target_term_id=seed_id, reason="USER_CORRECTED_NEGATION")
       │
       ▼ (Returned to CognitiveOrchestrator)
[Stage S10b Cognitive Core]
CognitiveOrchestrator.process()
  ├── Inspects pending `retraction_directives`
  └── Invokes existing kernel API:
      `invalidated_ids = reasoning_kernel.jtms.retract_premise(directive.target_term_id, arena)`
```

### 3.4 Why This Ownership Model is Strictly Superior
1. **Layer Integrity**: `LanguageIngressGate` remains a pure functional verification boundary. It inspects strings and discourse state; it does not touch `JTMS`.
2. **Deterministic Turn Ordering**: Retraction executes at the exact canonical point in the 16-stage cognitive pipeline (Stage S10b reasoning), preventing race conditions or mid-turn state tearing.
3. **P23-H Immutability**: `JTMS.retract_premise(premise_id, arena)` is an existing, fully verified method in `src/core/cognition/kernel/jtms.py`. Not a single line of P23-H code is altered.

## 4. Decision C — F12 Cross-Session Identity Scope

### 4.1 The Problem
`TermArena` is an in-memory preallocated ring buffer (`max_terms = 4096`). `term_id` is an integer index ($1 \dots 4096$). When the process restarts or an arena is cleared, `term_id` allocations are re-initialized. 

The question is whether ADR-038's causal link requires solving cross-session persistent identity (F12) before implementation can begin.

### 4.2 Audit of In-Session vs. Cross-Session Causal Realities
1. **In-Session Conversational Lifetime**:
   - Conversational causal attribution (`CONFIRMED_ECHO`, `CORRECTED_NEGATION`, `SUPPLIED_ANSWER`) operates across immediate dialogue turns within an active conversation (Turn $t-1 \to$ Turn $t$).
   - Within an active process session, `TermArena` allocations are strictly monotonic and immutable. `asst_term_id` allocated in Turn $t-1$ is guaranteed to retain its exact referent in Turn $t$.
2. **Cross-Session Interactions**:
   - A user closing the application, turning off the computer, and returning the next day does not utter an ungrounded bare echo (*"Yeah"*) or bare correction (*"No, I hate it"*) to a question asked 24 hours earlier.
   - Any multi-session topic resumption (*"Earlier this week you asked me about piano..."*) is an explicit conversational re-grounding that provides fresh natural language arguments, rather than an immediate conversational speech-act dependency.
3. **Premature Identity Architecture**:
   - Forcing ADR-038 to solve cross-session persistent proposition identity would require building a distributed UUID-to-integer mapping layer, database schema migrations, and cross-session graph re-indexing—none of which are needed for conversational anti-echo protection.

### 4.3 Ratified Decision (Decision C)
**ADR-038 causal linking is explicitly scoped to In-Session Conversational Lifetime (`LIFETIME: IN_SESSION`).**

1. `antecedent_term_id: int` is authoritative for the entire duration of the active conversational session.
2. Cross-session persistence of `TermArena` integer indices is **EXPLICITLY OUT OF SCOPE** and deferred to a dedicated Knowledge Persistence milestone.
3. Upon session termination or process exit, uncommitted ephemeral conversational candidate terms in `TermArena` are discarded; persistent factual propositions remain protected in `KnowledgeStore` and `SemanticGraph`.

## 5. Cross-Decision Consistency & End-to-End Data Flow

The three ratified decisions compose into an unbroken, non-circular execution flow:

```text
Turn t-1 (Assistant Inquiry Turn):
  1. Stage S10: CAPS decides to inquire: `INQUIRE(c:like, e:user, e:jazz)`
  2. Stage S10b: Orchestrator interns inquiry intent into `TermArena`:
     `asst_term_id = arena.allocate_term(pred=c:like, a0=e:user, a1=e:jazz, status=UNKNOWN, scope=MODAL)`
  3. Stage S10b: `DyadicDiscourseState` records:
     `active_assistant_seed_term_id = asst_term_id`, `inquiry_type = "CLOSED"`
  4. Stage S14: `PromptAssembler` realizes text: *"Do you like jazz?"*
  5. Stage S16: History append. (asst_term_id remains intact in TermArena and DyadicDiscourseState).

Turn t (User Response Turn):
  6. User inputs: *"No, I actually hate it."*
  7. Stage S1: `LanguageIngressGate` receives input_text and `DyadicDiscourseState`:
     - Reads `active_assistant_seed_term_id = asst_term_id`.
     - Analyzes speech act: Refutation of closed inquiry.
     - Sets `causal_relation = CORRECTED_NEGATION`, `antecedent_term_id = asst_term_id`.
     - Certifies candidate: `epistemic_status = FACT`, `polarity = False`.
     - Emits `RetractionDirective(target_term_id = asst_term_id)`.
  8. Stage S1: `ProjectGraphToTerms` allocates user term in `TermArena`:
     `user_term_id = arena.allocate_term(polarity=False, provenance=ProvenanceRecord(metadata={1001: 4, 1002: asst_term_id}))`
  9. Stage S10b: Orchestrator executes pending retraction:
     `reasoning_kernel.jtms.retract_premise(asst_term_id, arena)`
     (JTMS invalidates any inferences that depended on the assistant hypothesis).
  10. Stage S10b: P23-H resolves goals under Strong Kleene K3 using certified user fact.
```

### Consistency Verification Checklist
- [x] **No Circular Dependencies**: Ingress feeds Orchestrator; Orchestrator feeds Core.
- [x] **No Subsystem Inventions**: Uses existing `TermArena`, `ProvenanceRecord.metadata`, `DyadicDiscourseState`, and `JTMS`.
- [x] **P23-H Purity**: Zero lines of code modified in `src/core/cognition/kernel/`.
- [x] **Invariant NEG-02 Preserved**: Scalar confidence never asserts `FACT`.
- [x] **Prompting Invariant Preserved**: `prompted != epistemically dependent`.
