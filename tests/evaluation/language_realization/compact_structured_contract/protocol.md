## 1. Objective & Research Questions

### 1.1 Central Question
> *Does a compact structured realization contract (<80 tokens) preserve semantic fidelity between CAPS and natural language realization significantly better than the current flattened realization prompt, or do the intrinsic limitations of the 1.2B parameter realizer (established in Stage 3-B) dominate regardless of input formatting?*

### 1.2 Specific Goals
1. **Disentangle Structural Loss from Model Incapacity**:
   - Determine how much of the ~50.0–59.5% critical semantic error rate observed in Stage 3-A/3-B stems from **structural loss during prompt flattening** (GAP-01/GAP-05) vs **intrinsic SLM limitation** (inability to handle negation, refusal, or complex argument binding).
2. **Evaluate Contract Token Budget & Latency Overhead**:
   - Verify that the compact contract payload remains strictly under **<80 tokens**, introducing negligible inference and memory latency.
3. **Assess Phenomenon-Specific vs Global Remediation**:
   - Determine whether structured role and scope encoding cures argument inversions and epistemic distortions without risking semantic regression in other phenomena.

## 2. Experimental Design & Paired Setup

### 2.1 Paired Controlled Configuration
All variables are held strictly invariant between the two conditions:
* **Corpus**: Identical 42 structured fixtures from Stage 3-A/3-B (`audit_fixtures.json`).
* **Model Checkpoint**: Bit-exact `LFM2.5-1.2B-Instruct-Q4_K_M.gguf`.
* **Hardware & Backend**: NVIDIA GeForce RTX 3050 Ti Laptop GPU (`n_gpu_layers=32`), CUDA sm_86, `llama-cpp-python` v0.3.20.
* **Decoding Parameters**: `temperature = 0.3`, `max_tokens = 96`, `seed = 42`.
* **Evaluation Pipeline**: Identical Level 2/3 deterministic semantic evaluator and independent double annotator.

### 2.2 Conditions Tested

#### Condition A — Current Representation (Baseline)
* Uses the flattened realization directives generated by `PromptAssembler`:
  - `[DIRECTIVES]` block containing prose-like bullet points (act, target predicate, focus argument, epistemic status, polarity, constraints).
  - Graph edges, explicit argument slot bindings (`:ARG0`, `:ARG1`), scopes, and provenance are flattened into unstructured text.

#### Condition B — Compact Structured Contract (Experimental)
* Encodes minimal structured semantic elements into a compact YAML/key-value contract payload (<80 tokens):
  ```text
  [STRUCTURED REALIZATION CONTRACT]
  ACT: <COMMUNICATIVE_ACT> | POLARITY: <POS | NEG> | EPISTEMIC: <STATUS>
  EVENT: <TARGET_PREDICATE> | ARG0: <ARG0> | ARG1: <ARG1> | ARG2: <ARG2>
  SCOPE: <ROOT | MODAL_EMBEDDING | NEGATION_SCOPE> | PROVENANCE: <ORIGIN>
  RULE: <COMPACT_CONSTRAINT_RULES>
  ```
* Injected into the prompt replacing `[DIRECTIVES]`, preserving the identical system preamble, somatic state, communication strategy, and conversation context.

## 3. Metrics & Dimensions

### 3.1 Primary Comparative Metrics
1. **Critical Semantic Error Rate**:
   $$\text{ERR}_A = \frac{\sum \mathbb{I}[\text{Err}_A]}{N}, \quad \text{ERR}_B = \frac{\sum \mathbb{I}[\text{Err}_B]}{N}, \quad \Delta_{\text{ERR}} = \text{ERR}_B - \text{ERR}_A$$
2. **Transition Matrix (Status Changes)**:
   - `RESOLVED`: Error in Condition A $\rightarrow$ Pass in Condition B.
   - `REGRESSED`: Pass in Condition A $\rightarrow$ Error in Condition B.
   - `SAME`: Identical pass/fail outcome in both conditions.

### 3.2 Error Category Breakdown
- `ARGUMENT_ENTITY_LOSS`: Argument loss or role inversion (`:ARG0` $\leftrightarrow$ `:ARG1`).
- `CONTRADICTED`: Polarity failure or direct target contradiction.
- `EPISTEMIC_DISTORTION`: Epistemic promotion or hedging failure.
- `COMMUNICATIVE_ACT_FAILURE`: Refusal or clarification failure.
- `UNSUPPORTED_ADDITION`: Hallucinated entities or ungrounded claims.

### 3.3 Language & Phenomenon Breakdown
- Per-language error rates across English (EN), Vietnamese (VI), and Japanese (JA).
- Phenomenon-specific reductions across argument roles, polarity, scope, modality, and grounding refusal.

### 3.4 Efficiency & Overhead
- Average contract payload token count ($\text{Tokens}_{\text{contract}} < 80$).
- Total prompt token delta ($\Delta \text{Tokens}_{\text{prompt}}$).
- Inference latency delta ($\Delta \text{Latency}_{\text{ms}}$).

## 4. Decision Framework

The evaluation mandates selecting exactly one of the four verified verdicts:

1. **`Structural benefit supported`**:
   - Condition B significantly reduces critical semantic errors across multiple languages and categories (e.g. error rate $\le 20\%$, $\ge 15$ resolved errors), proving that structural loss was the primary bottleneck.
2. **`No meaningful benefit`**:
   - Condition B error rate is statistically indistinguishable from Condition A ($|\Delta| \le 5\%$), proving that 1.2B SLM capacity dominates completely.
3. **`Mixed / phenomenon-specific benefit`**:
   - Condition B resolves targeted structural failures (e.g., argument roles or epistemic hedging) but fails to resolve broader instruction-following weaknesses (e.g., negation polarity or ungrounded query refusal), with residual error rate remaining high ($\ge 35\%$).
   - *Implication*: The contract is architecturally sound and necessary, but insufficient alone without runtime fail-closed gating or larger parameter realizers.
4. **`Inconclusive`**:
   - Contradictory signals across languages or high regress-to-resolve ratio preventing unambiguous attribution.
